# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project shape

Slidev-based multi-deck presentation site deployed to GitHub Pages from `main:/docs`. There is no application code — just deck Markdown, shared styling, and Node build scripts that wrap `slidev build` / `slidev export`. Requires Node.js 22+.

## Critical: `docs/` is build output, not source

`docs/` is regenerated by `npm run build` and is the GitHub Pages publish source. **Never edit slides under `docs/`** — edits will be wiped. Always edit under `decks/` and rebuild. Because Pages serves from `main:/docs`, shipping deck content changes requires committing the rebuilt `docs/` along with the source change.

## Commands

```bash
npm install                                # Node 22+
npm run dev:<deck-key>                     # local Slidev preview for one deck
npm run build:<deck-key>                   # build one deck (HTML + PDF)
npm run build                              # clean, build all decks, build index, copy public assets
npm run clean                              # rm -rf docs/, dist/, decks/*/dist/
```

Deck keys: `semgrep`, `indirect-prompt`, `windows-design`, `mobile-audit-mcp`, `codex-deeplink-audit-guide`. Exact script names live in `package.json`.

`npm run build:<deck>` runs `scripts/build-deck.js <deck-folder-name>`, which (1) `slidev build` → `docs/<deck>/`, (2) `slidev export` → `docs/downloads/<deck>.pdf`, (3) injects a fixed-position "PDF 다운로드" link into the built `index.html` / `404.html`. The PDF export needs Playwright Chromium (`npx playwright install chromium --with-deps`).

## Deck layout

Two patterns coexist; pick the one that matches the deck you're editing:

- **Single-file deck** (`semgrep-android-local`, `indirect-prompt-injection`): everything in `decks/<deck>/slides.md`.
- **Split deck** (`windows-audit-design`, `mobile-audit-mcp-origin`, `codex-deeplink-audit-guide`): entry `decks/<deck>/slides.md` contains the title slide and a chain of `--- src: ./pages/NN_*.md ---` includes; per-slide bodies live in `decks/<deck>/pages/`.

Each `slides.md` imports `../../global.css` (and optionally a deck-local stylesheet) inside a top-level `<style>` block — keep that import when editing front matter.

## Adding a new deck

A deck is wired in five places. Miss any and it won't build or won't appear on the index:

1. `decks/<deck>/slides.md` (+ `pages/` if split).
2. `package.json` — add `dev:<key>` and `build:<key>` scripts.
3. `package.json` — append `&& npm run build:<key>` to the master `build` script chain.
4. `scripts/build-index.js` — add an entry to the `decks` array (`name`, `path`, `description`, `toc`). The path must end in `/`.
5. Run `npm run build`, then commit the regenerated `docs/`.

## Base path and site config

`scripts/site-config.js` derives the GitHub Pages base from `GITHUB_PAGES_REPO` → `GITHUB_REPOSITORY` → `git remote origin` → `package.json` name, in that order. `*.github.io` repos get `/`; everything else gets `/<repo>/`. Each deck builds with `--base /<repo>/<deck>/`. Override locally by setting `GITHUB_PAGES_REPO` if you need a different base when previewing the static output.

## Theming

`global.css` defines a `data-palette` system (`warm-gray`, `slate-gray`, `graphite`) with CSS custom properties (`--c-bg`, `--c-text`, `--c-accent`, …). The palette is applied at runtime by `public/palette.js`, copied to `docs/` by `scripts/copy-public.js` during `build:index`. `docs/index.html` (generated by `build-index.js`) re-declares the same palette tokens inline — if you add or rename a palette, update **all three**: `global.css`, `public/palette.js` (palette list), and the inline CSS + picker buttons in `build-index.js`.

## Deployment

`.github/workflows/deploy.yml` only verifies the build and uploads an artifact; it does not push. Actual deployment is GitHub Pages "Deploy from a branch" pointed at `main:/docs`, so committing the rebuilt `docs/` to `main` is what ships changes.
