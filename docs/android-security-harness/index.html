보안 분석 및 검증 Harness

AI 후보 분석과 단말 기반 검증 루프를 결합한 Android 보안 점검 체계

추진 배경 - 보안검토 업무량 증가

보안검토, APK 서명 리뷰, Spot 이슈 분석과 PLM 대응을 빠르게 처리해야 하는 운영 부담 확대

  • 2025년 보안검토 요청 건수 1,045건 · 연간 누적 검토 요청 기준
  • APK 서명을 위한 리뷰 건수 일 평균 약 150건 · 매일 처리되는 서명 전 검토 기준
  • 다량 분석 대응 Spot성 이슈 분석, PLM 등 다량의 분석을 빠르게 수행해야 함
  • 수작업 의존 후보 선별, 검증 계획 수립, 재현, 보고까지 수작업에 의존하여 일관성과 재현성 저하

추진 배경 - AI 분석 적용 시 문제점

AI는 분석 속도를 높일 수 있으나 보정, 검증, 결과 일관성 측면의 통제가 필요

  • 수작업 보정 필요 사람이 AI 분석 결과를 재확인하고 수정해야 하는 경우가 많음
  • 검증 없는 이슈 확정 재현 검증 없이 이슈를 확정하는 경우가 많아 False Positive 증가
  • 결과 변동성 동일 입력임에도 AI 분석 결과가 다르게 나오는 경우가 많아 점검 결과 신뢰성 저하
  • 관리 방향 AI 분석 결과는 확정 finding이 아니라 검증 대상 후보로 관리하고 evidence 기준으로 최종 채택

과제 목표

AI 기반 빠른 분석과 실단말 검증을 결합해 재현 가능한 보안 점검 체계 구축

  • 빠른 취약점 분석 AI를 사용해 보안 취약점 후보와 관련 근거를 신속하게 분석
  • 기존 Pain Point 해결 낮은 재현성, 과도한 수작업, 높은 False Positive 개선
  • 재현 가능한 보고 실단말 검증 Harness로 검증자가 쉽게 재현 가능한 보고서 작성
  • 목표 상태 AI 분석 결과를 실단말 재현 검증과 evidence를 포함한 보고서로 전환

기대 효과

분석 자동화와 단말 검증을 결합하여 finding 신뢰도와 운영 재현성 개선

  • 자동화 수준 향상 분석 후보 생성과 반복 증거 수집을 표준 루프로 구성
  • 단말 기반 재현성 확보 에뮬레이터 또는 테스트 단말 상태 기준으로 관찰 결과 보존
  • False positive 감소 재현 실패, 사전 조건 부족, 증거 부족을 finding 채택 전 분리
  • 복합 시나리오 확장 단일 rule hit가 아니라 chain, precondition, observation을 함께 판단

향후 계획 개요

역할 분리, Harness AI 학습·벤치마크, 평가 metric 기반 결론 도출로 다음 단계를 구분

01 단일 AI 구조 → 역할 분리 분석, 실행, 판정 책임을 분리하여 AI 결과를 바로 확정하지 않고 evidence 기반 검증 흐름으로 전환
  • Security AI: 검증 목표 정의
  • Harness AI: 허용 action 실행
  • Oracle: evidence 기준 판정
02 Harness AI 모델 선정·학습·벤치마크 저B 모델 후보를 선정하고 Android/ADB 실행 데이터로 학습한 뒤 자체 벤치마크로 운영 가능성을 검증
  • 대상 모델 선정
  • 도구 사용·복구 패턴 학습
  • Base vs Fine-tuned 비교
03 평가 metric 추출 및 결론 도출 실행 성공률, 실패 복구율, 증거 품질, 판정 정확도를 metric으로 추출해 도입 효과와 한계를 정리
  • Action success / recovery rate
  • Evidence completeness
  • FP 감소 및 운영 결론

단일 AI 구조의 한계

분석, 실행, 판정의 책임 경계가 다르므로 역할 분리 기반 통제 필요

단일 AI 흐름

요청 → 분석/판단 → 계획/결정 → 실행 → 증거 수집/판정 → 결과 보고
  • 분석과 실행 목표 혼재 가능성
  • 위험한 단말 동작 선택 가능성
  • 증거 부족 상태의 결론 생성 가능성

역할 분리 흐름

Security AI → Harness AI → Oracle → Proof State 갱신
  • Security AI가 검증 목표만 정의
  • Harness AI가 allowlisted action만 선택
  • Oracle이 evidence 기준으로만 판정

Verifier / Oracle

저장된 evidence와 oracle rule 기준으로 최종 상태를 판정

상태판정 의미처리 방향
Confirmed요구한 evidence와 oracle 조건 충족finding 후보로 채택 가능
Refuted관찰 결과가 가설 또는 oracle 조건과 불일치후보 제외 또는 가설 수정
Inconclusive증거 부족 또는 사전 조건 미충족추가 검증 목표로 회수
판정 원칙 Observation · trace · artifact · oracle rule 기반 판단 모델 설명만으로 최종 판단하지 않고 저장된 evidence를 기준으로 proof state 갱신
