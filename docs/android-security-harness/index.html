AI 후보 분석과 단말 기반 검증 루프를 결합한 Android 보안 점검 체계

추진 배경

Android 보안 점검의 범위 확대와 AI 후보 분석의 변동성을 통제할 검증 체계 필요

  • Android 점검 범위 확대 Manifest, decompiled code, runtime behavior, device state 동시 확인 필요
  • AI 후보 분석 통제 필요 동일 입력의 결과 변동, 근거 부족 추론, 사전 조건 누락 가능성 관리 필요
  • 재현 증거 기반 판단 실제 단말에서 재현되지 않는 후보를 finding으로 채택하지 않는 기준 필요
  • 분석과 검증 연결 AI 분석 결과를 실행 가능한 ProbeSpec과 evidence 수집 루프로 변환

과제 목표

AI 분석, 단말 검증, evidence 판정을 하나의 표준 절차로 구성

  • AI 기반 후보 도출 코드, Manifest, 리포트, 실행 흐름을 구조화해 후보 취약점 생성
  • 단말 기반 검증 루프 후보를 ProbeSpec으로 변환하고 허용된 action 안에서 재현 가능성 확인
  • Evidence 중심 최종 판단 모델 의견이 아니라 저장된 observation과 oracle rule 기준으로 판정

추진 방식

결정적 분석 틀을 먼저 고정하고 AI는 후보 생성과 검증 조정에 제한적으로 활용

AI에게 임의 탐색을 맡기기 전에 결정적 분석 틀과 구조화된 evidence를 먼저 제공

기대 효과

분석 자동화와 단말 검증을 결합하여 finding 신뢰도와 운영 재현성 개선

  • 자동화 수준 향상 분석 후보 생성과 반복 증거 수집을 표준 루프로 구성
  • 단말 기반 재현성 확보 에뮬레이터 또는 테스트 단말 상태 기준으로 관찰 결과 보존
  • False positive 감소 재현 실패, 사전 조건 부족, 증거 부족을 finding 채택 전 분리
  • 복합 시나리오 확장 단일 rule hit가 아니라 chain, precondition, observation을 함께 판단

단일 AI 구조의 한계

분석, 실행, 판정의 책임 경계가 다르므로 역할 분리 기반 통제 필요

단일 AI 흐름

요청 → 분석/판단 → 계획/결정 → 실행 → 증거 수집/판정 → 결과 보고
  • 분석과 실행 목표 혼재 가능성
  • 위험한 단말 동작 선택 가능성
  • 증거 부족 상태의 결론 생성 가능성

역할 분리 흐름

Security AI → Harness AI → Oracle → Proof State 갱신
  • Security AI가 검증 목표만 정의
  • Harness AI가 allowlisted action만 선택
  • Oracle이 evidence 기준으로만 판정

Verifier / Oracle

저장된 evidence와 oracle rule 기준으로 최종 상태를 판정

상태판정 의미처리 방향
Confirmed요구한 evidence와 oracle 조건 충족finding 후보로 채택 가능
Refuted관찰 결과가 가설 또는 oracle 조건과 불일치후보 제외 또는 가설 수정
Inconclusive증거 부족 또는 사전 조건 미충족추가 검증 목표로 회수
판정 원칙 Observation · trace · artifact · oracle rule 기반 판단 모델 설명만으로 최종 판단하지 않고 저장된 evidence를 기준으로 proof state 갱신
